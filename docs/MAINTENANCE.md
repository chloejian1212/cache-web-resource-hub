# Recommended Maintenance and Handoff Guide

[Project overview](../README.md) · [Resource model](INFORMATION_ARCHITECTURE.md)

This guide develops the project’s sustainability plan into a recommended workflow for the published resource hub. It incorporates concrete link observations from the [live-site review](LIVE_SITE.md), while leaving organizational ownership and approval of the workflow with CACHE.

## Ownership

| Responsibility | Recommended owner |
| --- | --- |
| Website and organizational content | CACHE |
| Approving new categories or structural changes | Designated CACHE website/content owner |
| Reviewing the relevance and quality of a resource | A designated reviewer with relevant subject knowledge |
| Updating pages and links | Authorized Squarespace editor |
| Reviewing usage and prioritizing improvements | Designated analytics/content reviewer |
| Supporting future project work | CACHE maintainers and any future student collaborators |

Roles can be combined when the team is small. The important requirement is a known owner for decisions and a clear record of what was changed.

## Adding a resource

1. **Check relevance.** Establish the resource’s purpose, intended audience, source, and relationship to CACHE’s topics.
2. **Check the destination.** Open the link and confirm that it reaches the intended material. Note a paywall, sign-in requirement, download, or known access restriction.
3. **Check for duplication.** Look for an existing listing of the same resource, including tracking-link variants.
4. **Choose a topic.** Use the [published page structure](INFORMATION_ARCHITECTURE.md#1-published-page-hierarchy) for placement. Keep the earlier planning taxonomy separate from live page names. Escalate a proposed new topic to the content owner.
5. **Write the listing.** Add a clear title, a concise description, source attribution, format, and any supported dates or regional information.
6. **Choose its placement.** Decide whether it belongs in the introductory selection or a further-resource group. Use the format groups actually supported on that page; treat additional quick-use sections as a new design decision.
7. **Review and preview.** Have another editor or reviewer check the entry. Preview the page on desktop and mobile, and inspect the link with a keyboard.
8. **Publish and record.** Use the organization’s approved Squarespace publishing process and note what changed, who reviewed it, and the review date.

The [proposed resource fields](INFORMATION_ARCHITECTURE.md#4-proposed-resource-fields) can be maintained in a shared working sheet if that fits the team’s process. They do not require a custom database.

## Reviewing existing resources

The original sustainability plan recommends quarterly or semiannual reviews. Choose a cadence the organization can maintain, with earlier review for high-priority or time-sensitive material.

At each review:

- Check whether links still reach the intended destination.
- Confirm that descriptions match the current material.
- Review publication dates, access conditions, and regional relevance.
- Remove duplicate listings or cross-link them consistently.
- Reconsider whether the starting selection still represents the most useful entry points.
- Correct inconsistent category labels and missing source information.
- Check page readability, navigation, and downloads on a small screen.

When a resource becomes unavailable, look for a legitimate replacement or publisher-maintained destination. Record the decision to replace, archive, or remove it rather than silently changing the meaning of the listing.

## Using analytics

Use available, correctly configured reporting to identify questions for investigation: Which resource pages receive visits? Which outbound links are used? Where do visitors leave or struggle to continue?

An increase in visits alone does not demonstrate that people found a useful resource. Combine available usage data with usability observations, and keep measurement definitions consistent when comparing periods or versions.

Before reporting an improvement, record the data source, date range, metric definition, relevant implementation dates, and known tracking limitations. No baseline values or improvement targets are asserted in this guide.

## Handoff package

Recommended handoff materials include:

- The current page hierarchy, historical content taxonomy, and an explanation of the difference.
- An up-to-date resource inventory with review owners.
- Instructions for the Squarespace editing tasks the organization actually uses.
- A record of implemented changes, separate from proposed changes.
- An anonymized summary of research findings and remaining questions.
- Analytics access and interpretation instructions for authorized maintainers.
- A list of incomplete work and sensible priorities for the next team.

Transfer access through the organization’s normal account and permission management. Keep credentials and participant records outside public repository documentation.

## Beginning a future project cycle

Start with the implemented-change record and current website, then compare them with the outstanding recommendations. Recheck important resource links and review the latest user needs before creating new pages or categories.

This avoids treating an old proposal as a finished implementation and helps the next team continue from the actual state of the hub.
